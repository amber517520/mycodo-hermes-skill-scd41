# 未來真控制：必要核准清單

**本階段不可執行。不是修改 approved 或 mode 就能啟用；程式没有 POST 或輸出執行器。**

在設計任何致動實作前，逐項留下人工核准／測試證據：

- [ ] 菇種由供應商確認，指定階段、溫濕度／CO₂ 參數與來源、核准者、核准日期。
- [ ] 霧化器／風扇 pulse 最大秒數、freshness、冷卻與禁用條件經人工確認。不能把 offline TEST 的 2／3／10／20 當預設。
- [ ] 在已部署的 Mycodo 版本驗證「帶持續時間」的精確 API、頻道辨識、單位、最大值與終止行為；網頁 5 秒成功不等於 API 對照已驗證。
- [ ] 只用裝置 UUID 與 output_id 映射，驗證 channel 0、GPIO5／16、HIGH、startup/shutdown OFF；缺關聯即停止。
- [ ] 核對 Pi 本地 Functions／安全 cutoff 是否真的存在。安裝紀錄列後備規則為待辦，不可聲稱已保護。
- [ ] Pi 本地硬性最大 ON 時間，不依賴 Windows、網路、LLM 或回呼；證明 laptop 睡眠、程序當機、網路斷線、Pi 重開與 API timeout 皆會關閉。
- [ ] 實體 water interlock 或同等可靠的缺水保護；目前沒有水位感測器，人工 config=true 不足以證明防乾燒。
- [ ] 持久化冷卻狀態、時鐘回跳／未來时间防護、原子更新；dry-run 計畫不得被記成真正開啟。
- [ ] 單一執行者鎖、併發／重試去重、執行次數與總時長限制、回讀輸出狀態；不明的請求結果不可盲目重送。
- [ ] 環境上限、互斥／同時運作策略、失效安全、人工 emergency stop 與不變的 B 箱隔離。
- [ ] TLS 主機名與信任鏈驗證、最小權限 API key；取得憑證信任不能靠跳過驗證。
- [ ] 秘密不得進命令列；進一步完成未知參數錯誤隱私強化，完整 audit 錯誤代碼、輸入型別 fuzz／防禦與輸出資料白名單。
- [ ] 在隔離測試設備／模擬 API 完成故障注入與 code review，取得使用者**重新明確核准**實體控制。

排程與真正 execute 機制皆屬另一階段。不可安裝上游 cron、shell 腳本、直接 pinctrl、SSH GPIO 或臨時 curl 作為替代。
