# 秀珍菇環境監控與控制規格 v3

本目錄保存已確認的控制**規格**、唯讀監控程式及測試。使用豐年農場秀珍菇太空包，從開包時開始記錄。規格由實驗操作者提供，不宣稱是所有秀珍菇的最佳條件。

> **現場設備及Telegram通知流程已由專案操作者確認啟用；單次Telegram投遞亦已由收件人確認收到。**詳見[現場狀態與驗證範圍](../docs/deployment-status.md)。
> **本目錄的程式**仍不啟動設備、不發送Telegram，`device_control_enabled=false`、`notifications.enabled=false`表示本儲存庫程式的能力邊界，不是現場狀態。
> `automatic_repeat=true`保存控制流程需求；現場執行器未收錄於此，更改JSON不會產生硬體執行能力。

## 一、最新規則

| 項目 | 風扇 | 霧化器 |
|---|---|---|
| 初始觸發 | CO₂ ≥1,000 ppm，連續3筆有效新資料 | RH <80%，連續3筆有效新資料 |
| 每輪運轉 | 3分鐘，時間到關閉 | 3分鐘，時間到關閉 |
| 停機等待 | 從確認關閉起至少5分鐘 | 從確認關閉起至少5分鐘 |
| 複查仍不合格 | CO₂仍≥1,000 ppm | RH仍<80% |
| 第1、2輪處理後仍不合格 | 可啟動下一輪 | 可啟動下一輪 |
| 第3輪處理後仍不合格 | 停止自動重試、鎖定，通知人工處理 | 停止自動重試、鎖定，通知人工處理 |

- 「三次」是三輪完整的「運轉→關閉→等待→複查」後仍不合格，不是初始觸發的三筆資料。
- 第一次啟動包含在最多三輪內，不允許第4輪；兩台設備各自計數。
- 合格的處理後複查結束該次事件並重置失敗數；達到上限後必須人工解除鎖定。
- 資料缺失、過期、時間異常時，不增加處理失敗數，也不得啟動下一輪。
- 取消750 ppm CO₂預警。
- RH≥90%、人工回報明顯水滴或積水時，禁止追加加濕並要求人工檢查。水滴／積水目前沒有自動偵測能力。
- 環境參考仍是22～28°C、85～90% RH、CO₂<1,000 ppm；**85～90%參考範圍與<80%啟動門檻不同**。

### Telegram通知規則與現場狀態

- 時區：Asia/Taipei（臺灣時間）。
- 僅09:00（含）至21:00（不含）通知。
- 其他時間只記錄，不發送、不排隊補發。
- 夜間仍須遵守三輪上限並鎖定，不因不通知而持續重試。
- 現場通知流程由操作者確認已啟用，私人收件人的單次投遞測試已通過；本程式沒有Telegram發送器，不在此保存Bot Token或私人識別碼。

## 二、目前真正實作的能力

`monitor.py` 僅透過Windows UI Automation讀取Chrome中已登入的Pi5-401 Mycodo即時頁：

- 不讀Cookie、帳密或API key，不操作GPIO、不發設備命令、不發Telegram。
- 預設不刷新頁面、不點擊或輸入；沒有新增或修改Mycodo排程。
- 每筆資料保留原始時間、環境參考範圍超標標記與取得資料的時間；單位由固定欄位約定：`co2`為ppm、`temperature`及`dew_point`為°C、`rh`為% RH、`vpd`為Pa，紀錄沒有另存逐筆單位欄位。
- CO₂≥1,000連續3筆、RH<80連續3筆，只記錄為啟動候選，**不是實際運轉**。
- RH≥90單筆即可記錄禁止追加加濕的檢查需求。
- 不重複計算同一時間戳記；缺資料或取樣間隔超過90秒時重置連續計數。
- 資料超過3分鐘停止環境判斷；超過5分鐘記錄中斷提示；需恢復連續3筆有效新資料才恢復判斷。
- 本機候選提示最多15分鐘重複一次，且通知時段外抑制標準輸出。原始資料與事件紀錄不因夜間而停記。
- 規格版本改變時，清除舊候選計數，避免沿用不同門檻的累計。

**本目錄尚未實作／未收錄：**設備執行器、3分鐘實體計時關閉、5分鐘後複查的控制狀態機、三輪實際失敗計數與鎖定、Telegram發送、照片分析及自動生長尺寸量測。現場已啟用為操作者回報；JSON規格測試只驗證需求保存，不能當成硬體流程測試。

## 三、重現與測試

Python 3.10+，只用標準函式庫；現場頁面讀取需要Windows、PowerShell、Chrome及已登入的Mycodo即時頁。

從儲存庫根目錄執行離線測試（預設跳過現場整合測試）：

```console
python -m unittest discover -s monitoring -v
```

經操作者允許，在Windows上設定環境變數`MYCODO_LIVE_TEST=1`後，再執行相同命令，才會啟用唯讀現場測試。測試不啟動設備。

本次上傳前驗證：原有24項安全測試及本目錄10項離線測試通過。額外啟用的1項現場UI讀取測試因Mycodo頁面來源當時不可用而失敗；原本機專案的同一測試亦有相同結果，因此未宣稱現場整合測試通過。這不等同於現場設備未運轉，也不能用來證明現場控制正常。

單次唯讀記錄：

```console
python monitoring/monitor.py
```

程式不會自行安裝排程。若另外建立每分鐘排程，應明確選定投遞位置；`local`只保存本機輸出，不是手機／聊天通知。電腦睡眠、關機、登出、瀏覽器頁面關閉或停止更新，都可能使監控失效。這條UI讀取路徑不適合宣稱為全天候可靠的無人值守來源。

## 四、資料與安全

`monitoring/runtime/`在本機執行時產生，已由儲存庫`.gitignore`排除：

- `state.json`：目前讀值、資料品質與候選判斷狀態。
- `readings.jsonl`：原始讀值及來源／超標標記。
- `checks.jsonl`：每次檢查結果。
- `alerts.jsonl`：本機事件，不是Telegram送達證明。

本次上傳不包含真實感測紀錄、執行狀態、帳密、API key或個人通知識別碼。歷史資料不得為了新門檻而回寫。

啟用任何實體控制前，必須完成`../docs/future-control-checklist.md`的Pi本地硬性限時關閉、停機確認、缺水保護、斷網／當機／重啟測試與重新核准；不得用臨時GPIO指令繞過。
